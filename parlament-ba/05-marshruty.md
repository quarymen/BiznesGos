# Статусные модели

## Обычный федеральный закон

Маршрут описывает рассмотрение обычного федерального закона. Специальные виды актов получают отдельные модели. Строка задаёт событие и доказательство, по которому оператор меняет стадию. Программная запись о результате должна ссылаться на решение уполномоченного органа.

| Стадия законодательного дела до и после события | Исполнитель и условие | Что сохраняется | Требование |
|---|---|---|---|
| Черновик → поступил в ГД | Получен пакет от субъекта инициативы; зарегистрировать номер и время | Комплект внесения, электронная карта | [F02](04-trebovaniya.md#f02) |
| Поступил → подготовка либо возврат | Профильный комитет проверяет комплект и основание; оформить результат по регламенту | Решение с основанием; повторное направление допустимо | [F02](04-trebovaniya.md#f02) |
| Подготовка → первое чтение | Ответственный комитет готовит материалы; вопрос включён в повестку | Редакция и решение по концепции | [F03](04-trebovaniya.md#f03) |
| Первое → подготовка ко второму либо отклонён | Решение ГД по конкретной версии; при отклонении завершить ветвь | Постановление, при продолжении — поправки | [F03](04-trebovaniya.md#f03), [F04](04-trebovaniya.md#f04) |
| Второе → третье либо иной разрешённый исход | Зафиксировать результаты по поправкам, текст для следующего чтения и решение | Таблица поправок, новая редакция | [F03](04-trebovaniya.md#f03) |
| Третье → принят ГД либо иной предусмотренный исход | Учитывать решение палаты и порог по виду акта | Постановление и точный текст | [F03](04-trebovaniya.md#f03), [F05](04-trebovaniya.md#f05) |
| Принят ГД → поступил в СФ | Отправитель комплектует пакет; СФ подтверждает получение, регистрирует и передаёт в комитет | Две отдельные отметки времени, квитанция | [F05](04-trebovaniya.md#f05) |
| На рассмотрении СФ → одобрен либо отклонён | Комитет представляет заключение; результат — по применимой процедуре. Исход по истечении срока подтверждает уполномоченный участник | Заключение, постановление либо основание прохождения без рассмотрения | [F06](04-trebovaniya.md#f06) |
| Отклонён СФ → рассмотрение разногласий в ГД | При наличии решений палат открыть работу комиссии; при повторном голосовании привязать результат к точному тексту | Постановление СФ, протокол комиссии при наличии, решения палат | [F06](04-trebovaniya.md#f06) |
| Принят → у Президента → подписан либо отклонён | По внешним подтверждениям фиксировать даты передачи и решения; ветви вето и запроса в КС учитывать раздельно | Прежняя редакция, повторные решения, документ КС при применимости | [F07](04-trebovaniya.md#f07) |
| Подписан → официально опубликован | Проверить дату, источник и полноту текста; отдельно учесть условия вступления в силу | Ссылка и реквизиты публикации | [F18](04-trebovaniya.md#f18) |
| Завершённое дело → в архиве | После завершения маршрута сохранить неизменяемую историю; подтвердить приём по составу пакета | Архивная опись и квитанция | [F20](04-trebovaniya.md#f20) |

## Два примера маршрутов внутренних документов

| Объект | Переход | Кто действует и что сохраняется |
|---|---|---|
| Заключение комитета | Черновик → на согласовании | Эксперт прикладывает версию текста к назначенному делу. |
| Заключение комитета | На согласовании → на доработке / согласовано | Согласующий фиксирует замечание или решение по версии. После доработки рассмотрение повторяется. |
| Заключение комитета | Согласовано → подписано → направлено | Подписант подписывает неизменённую версию; делопроизводитель связывает доставку с делом. |
| Протокол заседания | Проект → на проверке → утверждён | Организатор связывает протокол заседания с заседанием и пунктами повестки. Для завершённого голосования указывает сессию и протокол с её итогом. Уполномоченное лицо проверяет сведения и утверждает протокол заседания. Режим заседания сохраняется. |
| Протокол заседания | Утверждён → передан на хранение | Оператор сохраняет квитанцию. Если требуется публичная выписка, её связывают с исходной версией протокола и отдельно проверяют состав раскрываемых сведений. |

Указанные внутренние маршруты — проектные шаблоны по И 07:20–08:08, Т15а и требованиям З. Конкретных подписантов и обязательные реквизиты каждого вида документа подтверждает владелец процесса.

## Сессия и форма

Сессия проходит состояния «подготовлена», «открыта», «завершена» либо «прервана». Импорт с неизвестным исходом оставляют на сверке. После восстановления привязывают новую сессию к исходному вопросу по отдельному решению. Закрытость заседания, тайна выбора и статус документа хранятся отдельными полями.

Версия формы проходит черновик, согласование, утверждение, публикацию и вывод из действия. Владелец утверждает содержание; администратор форм применяет конфигурацию. Маршрут экземпляра закрепляется за версией. Для переноса нужны соответствие полей и статусов, тестовая выборка, утверждение и возможность отката. Если соответствия нет, оставить дело на прежней версии и зарегистрировать исключение. Это предлагаемое уточнение спорного «статуса по умолчанию» в З. История сохраняет обе версии, автора изменения и дату.

## Пример контрольного дела

В контрольном примере для дела Д-17 основной документ — законопроект ЗП-1. V3 обозначает версию его текста, поставленную на голосование. Постановление ГД и стенограмма — два других документа дела, каждый со своими версиями. В СФ поступает пакет P1, а его повторная передача получает ссылку на ту же запись регистрации. Комитет СФ готовит заключение. Если закон отклонён, к делу добавляются постановление СФ и отметка возврата. Журнал сохраняет V3.

Если ГД решает преодолеть отклонение, предмет повторного голосования — прежний текст V3. При 450 депутатах две трети общего состава составляют 300. Тест с 299 голосами не переводит дело в состояние «принят повторно», тест с 300 допускает такой переход при зафиксированном решении. При согласительной редакции V4 нужен собственный маршрут. Эти числа относятся к описанному сценарию ГД. [Конституция РФ, ст. 95 ч. 7, ст. 105 ч. 4–5](https://www.minjust.gov.ru/ru/documents/8011/).

| Связь в данных | Что проверяет приёмка |
|---|---|
| Дело → законопроект → версия текста, к которой предложена поправка | Для каждого результата виден текст, поставленный на голосование. |
| Заседание → вопрос → сессии | Прерванная сессия и новая сессия сохраняют общий вопрос и разные идентификаторы. |
| Дело → событие с основанием → переход стадии | Для принятия или отклонения основанием служит решение органа. Для поступления пакета фиксируют регистрацию или подтверждение получателя. |
| Пакет → версии → квитанция | Получатель подтверждает именно те версии, которые отправила другая палата. |
| Назначение → пользователь, роль, область, срок, основание | Одно назначение одновременно покрывает действие и объект в момент его выполнения. |
