# Матрица должностей, ролей и ограничений российского парламента

## Справочник всех ролей • 1 из 2

Матрица должностей и рабочих профилей российского парламента. Учебная модель: должность даёт основание, роль описывает действие, ограничение задаёт его границы.

| Код | Роль | Понятное описание |
| --- | --- | --- |
| R01 | Согласующий доступ | Решает, предоставить ли рабочий доступ в своей области. Не назначает на государственную должность. |
| R02 | Руководитель работ | Ставит поручения и проверяет результат у закреплённых исполнителей. Не выдаёт доступ по этой роли. |
| R03 | Владелец процесса | Согласует, как установленный процесс реализован в системе. Не меняет Регламент палаты. |
| R04 | Владелец формы | Утверждает содержание закреплённой формы документа. |
| R05 | Уполномоченный по допуску | Решает вопрос доступа к определённым ограниченным материалам при наличии компетенции. |
| R06 | Владелец обмена | Согласует, какие данные, кому и для чего передаются. |
| R07 | Владелец ресурса | Определяет разрешённое размещение информации на закреплённом ресурсе. |
| R08 | Администратор модели прав | Ведёт описание ролей и ограничений. Не назначает их пользователям своим решением. |
| R09 | Оператор выдачи доступа | Применяет уже согласованное назначение без расширения его содержания. |
| R10 | Оператор оргструктуры | Обновляет сведения о подразделениях по официальным основаниям. |
| R11 | Оператор статусов и аккаунтов | Учёт статуса и обслуживание аккаунта — два отдельных назначения. Создание аккаунта не создаёт статус. |
| R12 | Настройщик маршрутов | Настраивает утверждённый порядок прохождения документов. |
| R13 | Настройщик форм | Настраивает и выпускает уже утверждённые формы документов. |
| R14 | Настройщик обмена | Настраивает только согласованные подключения и передачу данных. |
| R15 | Контролёр безопасности | Разбирает результаты проверок и нарушения. Автоматические проверки выполняет система. |
| R16 | Аудитор | Проверяет действия и назначения в заданной области. Не проверяет собственное администрирование. |

Сохранены 32 позиции: R01–R31 исходного каталога и добавленная R32. R31 — признак внешнего пользователя. Это новая редакция определений; прежние широкие права к ней не прибавляются.

## Справочник всех ролей • 2 из 2

Матрица должностей и рабочих профилей российского парламента. Учебная модель: должность даёт основание, роль описывает действие, ограничение задаёт его границы.

| Код | Роль | Понятное описание |
| --- | --- | --- |
| R17 | Автор документа | Создаёт и редактирует разрешённый проект документа. |
| R18 | Регистратор | Принимает, регистрирует и направляет документы. Не меняет режим доступа без отдельного основания. |
| R19 | Исполнитель | Выполняет конкретное поручение и представляет результат. |
| R20 | Согласующий документ | Проверяет документ на назначенном этапе: согласует, возвращает или отклоняет. |
| R21 | Эксперт | Готовит заключение или проект поправки. Подготовка не равна формальному внесению. |
| R22 | Подписант | Подписывает предусмотренный документ в конкретном качестве: лично, от имени органа, при замещении или по специальному поручению. |
| R23 | Организатор и документатор | Подготовка заседания и оформление протокола — два отдельных назначения. Они не дают права подписи. |
| R24 | Участник голосования | Лично голосует там, где имеет решающий голос. |
| R25 | Оператор публикации | Размещает только разрешённые материалы на закреплённом ресурсе. |
| R26 | Участник заседания ГД | Участвует в указанном заседании ГД или её органа; получает только разрешённые материалы. Голосование требует R24. |
| R27 | Участник заседания СФ | Участвует в указанном заседании СФ или его органа; получает только разрешённые материалы. Голосование требует R24. |
| R28 | Участник парламентских действий | Совершает предусмотренные статусом действия: вносит законопроект, поправку, предложение или собственный запрос. Запрос палаты требует её решения. |
| R29 | Принимающий единоличное решение | Принимает перечисленные единоличные решения в своей компетенции. Не заменяет коллективное решение палаты или комитета. |
| R30 | Администратор платформы | Обслуживает инфраструктуру, копирование и восстановление. Не получает деловую подпись или голосование. |
| R31 | Внешний пользователь | Признак пользователя. Сам по себе не даёт операций с документами. |
| R32 | Председательствующий | Ведёт конкретное заседание по действительному основанию. Не получает автоматически все права руководителя. |

## Как применять матрицу и проверять корректность

Полный набор человека = роли по должности + отдельно подтверждённые рабочие профили. Каждое назначение сохраняет свои ограничения: область одной роли нельзя использовать для расширения другой.

| Что фиксируем | Пример |
| --- | --- |
| Роль и конкретное действие | R22 — подписать протокол заседания комитета СФ. |
| Объект и качество действия | Комитет А, заседание № …; подпись председательствующего. |
| Основание и срок | Статья 32 Регламента СФ; лицо действительно вело это заседание. |
| Проверка перед выполнением | Проверить подписываемую версию, орган и основание. R22 другого документа не даёт права подписать этот. |

Что изменено в каталоге

R26/R27 уточнены для конкретных заседаний палаты и её органов. R28 дополнена внесением законопроекта в установленной процедуре; собственный запрос парламентария отделён от парламентского запроса палаты. R11 и R23 сохранены под прежними кодами, но внутри них назначаются независимые профили. Это предложения к модели, а не новые нормы Регламентов.
